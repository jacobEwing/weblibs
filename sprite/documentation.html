1. Quick start

Two classes. A SpriteSheet holds an image, the frames cut from it, and the animation sequences that stitch those frames together. A Sprite is one live instance you can position, animate, and draw.

// 1. Load a sheet once, at startup.
const sheet = await SpriteSheet.load('sprites/player.json');

// 2. Make a sprite from it.
const hero = sheet.newSprite();
hero.setPosition(100, 100);
hero.setScale(2);
hero.setFrame('front_idle');

// 3. In your frame loop: update the clock, then draw.
function frame(now) {
	const dt = now - last; last = now;

	hero.update(dt);        // dt in milliseconds
	hero.draw(ctx);

	requestAnimationFrame(frame);
}

The single most important thing: animations do not advance on their own. Nothing happens inside a sprite between calls to update(). If you forget to call it, sprites freeze on frame 0.

2. Mental model

The library separates three concerns that the old API mixed together:

ConceptLives inWhat it is
Sheet SpriteSheet A single image plus the frame rectangles cut from it. Immutable after loading. Every sprite points back at one sheet.
Frame sheet.frames[name] A rectangle { x, y, width, height, centerx, centery } describing one image region and its origin.
Sequence sheet.sequences[name] An ordered list of frame names, a rate, and an iteration count. Definitions, not state.
Sprite Sprite One instance: position, rotation, current frame, playback state, children. Mutable, cheap, disposable.

Because sheets are read-only and sprites are disposable, several sprites can share a sheet without any reference counting, and you can safely build and throw away sprites mid-frame.

3. Loading sheets

From a URL

SpriteSheet.load() fetches the JSON, then loads the image it points at. It's a static async factory — you never construct a sheet yourself.

const sheet = await SpriteSheet.load('sprites/player.json');

Relative image paths

Image paths inside the sheet JSON resolve relative to the JSON file, not the page. A sheet at sprites/player.json whose "image" is "player.png" loads sprites/player.png. This makes sheet folders relocatable — move sprites/ anywhere and everything still works.

Override the base explicitly if your sheets live somewhere unusual:

const sheet = await SpriteSheet.load('player.json', {
	baseUrl: 'https://cdn.example.com/art/'
});

From a plain object

Useful for tests, generated sheets, and the editor. The object is not mutated, so you can reuse it.

const sheet = await SpriteSheet.fromJSON({
	image: 'player.png',
	frameWidth: 24,
	frameHeight: 24,
	frames: {
		idle: { col: 0, row: 0 },
		walk: { col: 1, row: 0 }
	}
});

From a canvas or ImageBitmap

setImage() accepts any CanvasImageSource, not just a URL. This is how the editor will hand you procedurally-generated or user-dropped images.

const canvas = document.createElement('canvas');
// ...draw something onto canvas...

const sheet = await SpriteSheet.fromJSON({
	image: canvas,
	frameWidth: 16,
	frameHeight: 16,
	frames: { /* ... */ }
});

Once loaded, sheet.ready is true and newSprite() will work. Calling newSprite() on an unready sheet throws.

4. Sheet JSON format

Here's the player sheet, annotated. Everything except frames is optional.

{
	"image":       "player.png",   // relative to this JSON file
	"frameWidth":  24,            // tile size; used by col/row below
	"frameHeight": 24,
	"frameRate":   10,            // default frames per second
	"centerx":     0,             // default origin (see below)
	"centery":     0,

	"collision": {                 // optional, see §8
		"radius":  2,
		"offsetX": 0,
		"offsetY": -1
	},

	"frames": {
		"left_idle": { "col": 0, "row": 0 },
		"left_step_1": { "col": 1, "row": 0 },
		// ...
	},

	"sequences": {
		"walkleft": {
			"frames": ["left_step_1", "left_step_2", "left_step_3"]
		},
		"attackleft": {
			"frames": ["left_sword_2", "left_sword_1", "left_sword_3", "left_sword_1"],
			"iterations": 1
		}
	}
}

Frame keys

All keys are case-insensitive and leading/trailing whitespace is ignored. A frame's position is accumulated, so you can mix and match:

KeyEffect
colAdds col × frameWidth to the frame's x.
rowAdds row × frameHeight to the frame's y.
x, left, xoffsetAdds the value (in pixels) to the frame's x. All three are aliases.
y, top, yoffsetAdds the value (in pixels) to the frame's y. All three are aliases.
widthOverrides the frame's width. Defaults to frameWidth.
heightOverrides the frame's height. Defaults to frameHeight.
centerx, cxSets the frame's origin x. Defaults to the sheet's centerx.
centery, cySets the frame's origin y. Defaults to the sheet's centery.
drawOffsetAn {x, y} nudge applied at draw time only. Does not affect collision or origin.

Because col and x both add to the same value, they compose. { "col": 2, "xoffset": 1 } gives an x of 2 × frameWidth + 1.

Sequence keys

KeyDefaultMeaning
frames[]Array of frame names, in play order. Names must exist in frames.
frameRatesheet's frameRateFrames per second.
iterations00 loops forever. 1 plays once. n plays n times total. Any finite count fires the completion callback.
frameTimes—Per-frame durations in milliseconds. When present, overrides frameRate. Wraps if shorter than frames.
callback—Function invoked when a finite sequence completes. Only when written in JS, not loadable from JSON.
method'auto'Retained for compatibility. Under the current runtime this has no effect — see §7.

6. Sprite API

Construction

Always via the sheet: sheet.newSprite(). The Sprite constructor also accepts a sheet, but newSprite() is the sanctioned path — it enforces ready and applies sheet.scale.

Transform properties

PropertyDefaultMeaning
position{x: 0, y: 0}Where the sprite's origin lands in the parent's coordinate space. Mutate directly or use setPosition().
drawOffset{x: 0, y: 0}Applied at draw time only. Does not affect collision.
scale1Uniform scale. Applied to both position and drawing.
rotation0Radians, clockwise. Rotates around the sprite's origin.
flipX, flipYfalseMirrors around the origin without needing negative scale.
opacity1Multiplied into ctx.globalAlpha for this sprite and its children.
visibletrueWhen false, draw() returns immediately. Children are not drawn either.
zIndex0Used only for parent/child ordering. See §9.

Convenience methods

hero.setPosition(100, 50);
hero.setScale(2);
hero.rotate(Math.PI / 4);   // adds to current rotation

Frame state

Property / MethodNotes
frameThe current frame object, or null.
frameNameThe current frame's name, or null.
setFrame(name)Throws if the frame doesn't exist. Returns the sprite.
clearFrame()Clears the frame; the sheet's full image is used as a fallback.
frameWidth, frameHeightGetters. Current frame's size, falling back to the sheet's tile size.

Drawing

hero.draw(ctx);
hero.draw(ctx, { x: 200, y: 100, scale: 3 });

draw() honours visible, opacity, rotation, flipX/flipY, and any drawOffset on the frame. Options override the sprite's own values for that call only:

OptionOverrides
x, yposition (before drawOffset is added).
scalesprite.scale.
frameX, frameYSource rect origin. Rarely needed; mainly for slicing odd shapes.
frameWidth, frameHeightSource rect size.
centerx, centeryOrigin override.

Direct blits

Two lower-level helpers bypass the sprite's transform, origin, and rotation. Useful for tiles and background decoration where you want raw pixel control.

// Copy a specific region of the sheet.
hero.drawArea(ctx, dx, dy, sx, sy, sw, sh, scale);

// Copy a pseudo-random region — handy for rubble, foliage, stars.
hero.drawRandomArea(ctx, dx, dy, width, height, randomKey);

drawRandomArea picks a stable region for a given randomKey. Pass the same key for the same cell and you get the same art every frame; pass undefined and you get true randomness.

7. Animation

Four methods and one tick call.

hero.play('walkleft');                   // start; replaces any running sequence
hero.play('attackleft', {
	onComplete: () => hero.play('front_idle')
});

hero.update(dtMs);                     // advance the clock
hero.stop();                           // cancel, no callback fires

hero.animating;                        // boolean
hero.sequenceName;                     // 'walkleft' or null

Nothing animates on its own

The runtime is passive. Between calls to update(), nothing happens. This is deliberate — it lets you drive animation from your game loop, pause everything by skipping the update, and step frame-by-frame in the editor.

If a sprite looks frozen on its first frame, check that update() is being called every tick. dtMs is in milliseconds; if your loop measures in seconds, multiply by 1000.

Sequence completion

The completion callback fires when a sequence with a finite iterations count finishes. A looping sequence (iterations: 0, the default) never fires it.

On completion the sprite holds its final frame. That's the natural moment to chain:

hero.play('attackdown', {
	onComplete: () => hero.setFrame('front_idle')
});

Frame rate vs. frame times

For uniformly-paced animation, use frameRate (frames per second):

"walkleft": {
	"frames": ["left_step_1", "left_step_2", "left_step_3"],
	"frameRate": 8
}

For per-frame timing — a hold on one pose, a slow windup, a snap on the hit — use frameTimes (milliseconds each):

"attackleft": {
	"frames": ["left_sword_2", "left_sword_1", "left_sword_3", "left_sword_1"],
	"iterations": 1,
	"frameTimes": [120, 60, 80, 60]
}

frameTimes wins over frameRate when both are present. If it's shorter than frames, it wraps.

Long stalls

If update() is called with a very large dt — tab switch, debugger pause — the runtime stops fast-forwarding after 512 iterations and resets the accumulator. You won't see an animation race through its whole sequence at high speed.

About method

The old library had a method: 'auto'|'manual' flag that decided whether a sequence advanced itself. In the new runtime there's no self-driving path, so method is inert. "Manual" now just means "don't call update() on it." It's still parsed and preserved by toJSON(), so old sheets round-trip cleanly.

8. Collision

A sheet can declare a collision footprint that scales with the sprite. It's attached to the sheet, not the sprite, because shape is a property of the artwork.

Single-circle shorthand

"collision": {
	"radius":  2,
	"offsetX": 0,
	"offsetY": -1
}

Multi-circle form

For long or oddly-shaped entities, use several circles:

"collision": {
	"circles": [
		{ "radius": 4, "offsetX":  0,  "offsetY": -6 },
		{ "radius": 4, "offsetX":  0,  "offsetY": 2 }
	]
}

Offsets are relative to the sprite's origin, so a footprint that sits at the character's feet typically uses negative offsetY.

Radius is in sheet pixels, not scaled pixels. Multiply by sprite.scale if you need screen-space distances.

9. Parent / child sprites

Children are drawn inside the parent's transform. A child at (0, 0) sits on the parent's origin, which makes equipment, held items, and mounts natural to author.

const sword = swordSheet.newSprite();
hero.attach(sword);              // or: sword.attachTo(hero)

sword.position.x = 8;
sword.position.y = -4;

// Now drawing the hero draws the sword too, in the hero's space,
// rotated and scaled along with it.
hero.draw(ctx);

Draw order

Children are drawn in two passes, split by their zIndex sign:

  • Children with zIndex < 0 draw behind the parent.
  • Children with zIndex ≥ 0 draw in front.

Within each pass, draw order follows insertion order. So to make a sword sit behind the body while facing away, set sword.zIndex = -1; to bring it forward when facing the camera, set it back to 0.

// Facing away from camera: weapon hidden behind the body.
sword.zIndex = hero.facing === 0 ? -1 : 0;

Detaching and destroying

hero.detach(sword);        // remove a specific child
sword.detach();            // detach from its own parent

hero.destroy();            // stops animation, drops children, unlinks from parent

destroy() is what you want when a sprite goes away for good. Detaching is enough if you'll reuse it.

10. Serialisation

sheet.toJSON() returns a plain, JSON-safe object you can stringify and reload. This is the format the editor uses for save/load, and it round-trips.

const sheet = await SpriteSheet.load('sprites/player.json');
const copy  = sheet.toJSON();

// copy can be passed straight back to fromJSON():
const reloaded = await SpriteSheet.fromJSON(copy);

What's preserved

  • image (as imageSrc, or null for canvas sources).
  • frameWidth, frameHeight, centerx, centery, frameRate.
  • Every frame, with pixel coordinates normalised to x/y.
  • Every sequence, with frameRate, iterations, method, and frameTimes. Defaults are omitted.
  • The collision block, if present.

What's dropped

Function callbacks on sequences. They can't survive JSON, and reloading without them is the intended behaviour — attach callbacks at the call site with play(name, { onComplete }) instead.

11. Live demo

This demo generates a four-frame sprite sheet on a canvas at runtime, builds a SpriteSheet from it, and drives a Sprite through the API. No external files are involved.

For the demo to run, sprite.js must sit next to this HTML file. The rest of the document works standalone.

Loading…

// Build a sprite sheet from a canvas we draw ourselves.
function makeSheetImage() {
	const c = document.createElement('canvas');
	c.width = 64; c.height = 16;
	const ctx = c.getContext('2d');
	const colours = ['#d04040', '#40a040', '#4040d0', '#d0a020'];
	for (let i = 0; i < 4; i++) {
		ctx.fillStyle = colours[i];
		ctx.fillRect(i * 16, 0, 16, 16);
	}
	return c;
}

const sheet = await SpriteSheet.fromJSON({
	image: makeSheetImage(),
	frameWidth: 16,
	frameHeight: 16,
	frames: {
		f0: { col: 0, row: 0 },
		f1: { col: 1, row: 0 },
		f2: { col: 2, row: 0 },
		f3: { col: 3, row: 0 }
	},
	sequences: {
		cycle: { frames: ['f0', 'f1', 'f2', 'f3'], frameRate: 4 }
	}
});

const sprite = sheet.newSprite();
sprite.play('cycle');

12. Migrating from the old API

If you're porting code that used cSprite and spriteSet:

OldNew
new spriteSet(); await s.load(f)await SpriteSheet.load(f)
new spriteSet(); s.loadJSON(data)await SpriteSheet.fromJSON(data)
new cSprite(sheet)sheet.newSprite()
sprite.startSequence(name)sprite.play(name)
sprite.startSequence(name, cb)sprite.play(name, { onComplete: cb })
sprite.stopSequence()sprite.stop()
sprite.currentSequencesprite.sequence
sprite.currentFramesprite.frame
sprite.templatesprite.sheet
sprite.myParentsprite.parent
setTemplate()Removed — construct via sheet.newSprite()
resolveImageDimensions()Removed — imageWidth/imageHeight are getters
setFrameSize(w, h)Assign sheet.frameWidth / frameHeight
load_frames()loadFrames()
load_sequences()loadSequences()
parseCollision()Removed — handled internally during load

Behavioural changes worth knowing

  • Nothing animates on its own. You must call sprite.update(dtMs) each frame.
  • frameRate is frames per second, not milliseconds per frame. Old value 40 (40 ms) is now 25.
  • Frame x/y are now pixel offsets. Grid indices moved to col/row. Old sheets that used "x": 2, "y": 1 meaning tile coordinates need converting to "col": 2, "row": 1.
  • The completion callback fires for any finite iterations, not just 1. A sequence with iterations: 3 calls back after the third pass.
  • Image paths resolve relative to the sheet JSON, not the page.

13. Common gotchas

Sprites freeze on frame 0

Almost always a missing update() call. Also check your units — update() takes milliseconds. If your loop computes dt in seconds, multiply by 1000 first.

newSprite() throws "sheet is not ready"

You're calling it on a sheet that hasn't finished loading, or on one you constructed with new SpriteSheet() directly. Always use SpriteSheet.load() or SpriteSheet.fromJSON() and await them.

Sprites land at half their intended position

If everything drawn via draw() is off but drawArea() looks right, you probably have a scale mismatch. draw() multiplies x/y by scale internally; feed it world coordinates, not screen coordinates.

Animation callback never fires

The sequence is looping (iterations: 0 or omitted). Set iterations to a positive number. Also make sure you're passing a function — { onComplete: {...} } with an object is silently ignored.

Frame not found

Typo in a sequence's frames array, or the frame wasn't defined. Run sheet.validate() after loading to catch every one at once:

for (const { sequence, frame } of sheet.validate()) {
	console.warn(`sequence "${sequence}" references missing frame "${frame}"`);
}

Rotation accumulates instead of setting

rotate() adds to the current rotation, matching the old API. To set it, assign directly: sprite.rotation = Math.PI / 2. Calling rotate() inside your render loop will spin the sprite.

Child sprite draws in the wrong order

Ordering is by the sign of zIndex, not by magnitude. A child with zIndex: -5 draws behind the parent; a child with zIndex: 0 draws in front. There's no way to interleave multiple children around the parent.
